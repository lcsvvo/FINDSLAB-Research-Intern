04

왜 이렇게 운영하나

배경 설명. 실행에는 필요 없지만 판단이 헷갈릴 때 펼쳐본다.

왜 이 공간을 쓰는가
  • 연구실 공유 공간 — 개인 메모장이 아니다. 나만 알아보면 되는 기록은 맞지 않음.
  • 읽는 사람 기준 — 교수님 · 공동연구자가 페이지 하나만 보고 맥락을 이해할 수 있어야 함. 유일한 품질 기준.
  • 기록 = 연구 이력 — 연구가 끝나도 지우지 않고 상태만 종료로 변경.
  • AI로 작성해도 형식은 동일 — Claude로 초안을 빠르게 만들어도 STYLE_GUIDE · TEMPLATE 골격은 그대로. 가치는 "누가 만들었나"가 아니라 "표준에 맞는가"로 판단.
왜 운영 규칙 / 작성 규칙을 나눴나

둘을 한 문서에 섞으면 하나가 바뀔 때마다 다른 쪽까지 뒤져야 한다. 나눠 두면 "어디"가 바뀔 때는 운영 규칙만, "어떻게"가 바뀔 때는 작성 규칙만 고치면 된다 — 한 정보 = 한 자리 원칙을 문서 자체에도 적용.

05

가장 헷갈리는 지점

신규 팀원이 가장 자주 묻는 네 가지.

회의록 vs 의사결정 기록
  • 회의록 — 무슨 논의 · 피드백이 있었는가까지만. 미확정 사안도 포함.
  • 의사결정 기록 — 실제로 되돌리기 어렵게 확정된 결정과 근거 · 기각 대안만. 상태는 "확정" 또는 "재검토 필요".
  • 회의록이 먼저, 결정이 확정되면 의사결정 기록으로 옮겨져 근거 회의로 연결.
관찰 vs 해석, 왜 분리하는가
  • 관찰 — 데이터에서 직접 확인되는 사실(숫자·방향·패턴). 섹션마다 ### 관찰 결과.
  • 해석 — 관찰을 근거로 한 주장. 전체 끝나고 ## 해석에 한 번만.
관찰전기전자 평균 수익률 0.000812로 최대, 철강금속 변동성 0.0184로 최대.
해석산업마다 수익·위험 성격이 달라 금리 반응(베타)도 다를 여지가 있다.

"때문에" · "의미한다" · "여지가 있다" 같은 인과·의미 표현이 들어가면 이미 해석.

STEP 표기 — 파일명에는 왜 안 쓰는가
  • 파일명 — NN_stage.ipynb만. 예: 01_data_preparation.ipynb. STEP 단어 금지.
  • 문서 내부 제목(H1) — STEP{N}. 표기 사용. 예: # STEP1. 데이터 준비.
  • 파일명은 정렬 · 탐색용 순번, STEP 표기는 사람이 읽는 라벨. 역할이 다르므로 위치도 다름.
"원본은 옮기지 않지만 설명은 충분히"
  • 전체 코드 · 전체 표 · 대용량 데이터 · 이미지 원본은 Notion으로 옮기지 않음. 원본은 원래 저장 위치에 두고 링크만 건다.
  • 옮기지 않는 것은 원본이지 설명이 아님. 목적 · 입력 데이터 · 핵심 결과 · 해석은 Notion만 봐도 이해되게 풀어 써야 함.
  • "링크만 걸면 된다"는 틀린 판단. 문제는 겹침이 아니라 설명 부족.
06

흔한 실수 (안티패턴)

실제로 자주 나오는 위반 패턴 6가지.

관찰에 해석 섞기

"~때문에" "~로 보인다" 같은 주장이 관찰에 섞임. 관찰은 숫자·방향·패턴만.

여러 곳에 중복 기록

같은 내용을 회의록 · 의사결정 기록 양쪽에 상세히 씀. 한 정보는 한 자리, 나머지는 링크.

속성에 긴 설명 몰아넣기

Notion 표(속성)에 문단 단위 설명. 속성은 키워드 · 관계만, 상세 설명은 본문에.

파일명에 STEP 붙이기

STEP01_data.ipynb처럼 파일명에 STEP. 파일명은 01_data_preparation.ipynb 형식만.

Takeaway 누락

Summary 최상단에 Takeaway 없이 바로 본문. 항상 최상단 3~5줄 필수.

이모지 · 장식 사용

강조는 핵심 숫자 · 결론에 굵게만. 이모지, 화려한 장식은 쓰지 않는다.

07

용어 사전

자주 등장하지만 헷갈리기 쉬운 용어만 모았다.

STEP
노트북·요약 문서 내부 제목에만 쓰는 표기(STEP1.). 파일명에는 쓰지 않는다.
Takeaway
노트북 요약과 Summary 최상단에 오는 핵심 결과·의미 3~5줄 요약.
관찰 / 해석
관찰=데이터에서 확인되는 사실, 해석=그 사실을 근거로 한 주장. 반드시 분리해서 작성.
Summary
results/{카테고리}/summary.md. 해당 STEP 결과를 1페이지 이내로 압축한 문서.
진행 보고
2주마다 교수님께 공유하는 Notion DB. Workspace의 최우선 산출물.
연구 산출물
노트북·src 실행으로 생성된 Summary·Figure·Table·Dataset·Variable의 현황을 관리하는 DB.
데이터 카탈로그
원자료의 수집자·출처·상태 등 메타데이터만 관리하는 DB. 실제 데이터 파일은 넣지 않고 저장 위치만 남긴다.
Source of Truth
하나의 정보를 원본으로 관리하는 단 하나의 자리. 다른 곳에는 링크나 요약만 둔다.
문서 우선
운영 규칙이 바뀔 때는 Notion을 먼저 고치지 않고 문서(NOTION_WORKSPACE.md)를 먼저 고친 뒤 Notion에 반영한다.
