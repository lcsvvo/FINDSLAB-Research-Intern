SECTION 01

왜 config를 쓰나

결론부터. 각자 PC 경로를 코드에 적으면 남의 코드가 안 돌아간다.

문제 상황

config 없이 — 이렇게 하면

# 지우 노트북 df = pd.read_csv("C:/Users/jiwoo/Desktop/GitHub/ FINDSLAB/data/processed/panel.csv") # 수현이가 그대로 실행하면 FileNotFoundError

경로를 각자 고쳐야 한다. 고치다 보면 어느 순간 서로 다른 파일을 읽고 있다.

config 쓰면 — 이렇게 된다

# 누가 실행하든 동일 import config df = pd.read_csv(config.PANEL_PATH) # 지우 PC, 수현 PC, 정현 PC 전부 정상 동작

저장소를 어디에 두든 동작한다. 바탕화면이든 문서 폴더든 상관없다.

어떻게 가능한가

config.py는 자기 파일 위치(__file__)를 기준으로 프로젝트 루트를 찾는다. 현재 작업 폴더(cwd)에 의존하지 않는다.

# config.py 내부 PROJECT_ROOT = Path(__file__).resolve().parent # → config.py 가 있는 폴더 = 저장소 루트 DATA_DIR = PROJECT_ROOT / "data" H1_TABDIR = PROJECT_ROOT / "results" / "H1_yield_curve" / "tables"

얻는 것 네 가지

1
경로 수정 없이 그대로 실행

팀원 PC가 Windows든 Mac이든, 저장소가 어디 있든 동작한다.

2
파일명이 달라도 흡수

원본 파일명이 팀원마다 조금씩 달라도 별칭(alias)으로 찾아준다. .csv·.xlsx·.xls를 모두 인식한다.

3
엉뚱한 파일을 읽는 사고 차단

탐색을 프로젝트 폴더 안으로만 제한한다. 다른 프로젝트의 동명 파일이 잡히지 않는다.

4
무엇을 읽었는지 추적 가능

config.describe()로 실제 잡힌 파일을 확인할 수 있다. 재현성 검증에서 "무엇을 읽었나"는 반드시 확인해야 한다.

SECTION 02

설치 — 딱 한 번

각자 PC에서 한 번만 하면 된다. 그 뒤로는 신경 쓸 일이 없다.

1
저장소 루트로 이동

config.py와 requirements.txt가 둘 다 보이는 폴더다.

# Windows PowerShell cd C:\Users\내이름\...\FINDSLAB-Research-Intern # Mac / Linux cd ~/.../FINDSLAB-Research-Intern
2
편집 가능 모드로 설치

마지막 점(.)까지 포함해서 그대로 입력한다.

pip install -e .
3
확인

노트북이나 파이썬에서 아래를 실행해 경로가 뜨면 끝이다.

import config config.describe()
-e가 붙는 이유

editable(편집 가능) 모드로 설치한다는 뜻이다. 파일을 복사해 두는 게 아니라 저장소를 직접 바라보게 만든다.

그래서 팀원이 보내준 새 config.py로 덮어쓰기만 해도 재설치 없이 바로 반영된다.

가상환경을 쓴다면

가상환경을 켠 상태에서 설치해야 한다. 가상환경마다 한 번씩 필요하다.

# 가상환경 활성화 후 pip install -e . pip install -r requirements.txt

규칙은 하나다 — 경로는 전부 config에서 가져온다.

노트북 첫 셀

읽기

panel = pd.read_csv(config.PANEL_PATH, encoding="utf-8-sig") ext = pd.read_csv(config.EXTENDED_PANEL_PATH, encoding="utf-8-sig") yields = pd.read_csv(config.RAW_YIELD_CURVE_FILE, encoding="utf-8-sig")

쓰기

# 표 저장 — 가설별 폴더가 이미 만들어져 있다 df.to_csv(config.H2_TABDIR / "up_down_beta_by_industry.csv", index=False, encoding="utf-8-sig") # 그림 저장 fig.savefig(config.H2_FIGDIR / "up_down_beta_ci.png", dpi=200, bbox_inches="tight")
폴더를 미리 만들 필요 없다

config.py가 import될 때 results/ 하위 폴더를 전부 자동 생성한다. mkdir을 따로 쓰지 않아도 된다.

SECTION 05

자주 하는 실수

이 네 가지만 피하면 된다.

1. 경로를 문자열로 쓴다

df.to_csv("results/H2_asymmetry_regime/ tables/result.csv")

노트북을 어디서 여느냐에 따라 엉뚱한 곳에 저장되거나 에러가 난다. 폴더 이름이 바뀌면 전부 고쳐야 한다.

이렇게

df.to_csv(config.H2_TABDIR / "result.csv", index=False, encoding="utf-8-sig")

어디서 실행하든 같은 곳에 저장된다.

2. config 변수를 노트북에서 덮어쓴다

config.EXTENDED_PANEL_PATH = ... PANEL = "data/processed/panel.csv"

셀을 순서대로 실행하지 않으면 NameError가 나거나 config와 값이 어긋난다.

이렇게

# 별칭을 만들지 말고 매번 config에서 pd.read_csv(config.EXTENDED_PANEL_PATH)

값이 한 곳에서만 관리된다.

3. describe() 안 보고 시작한다

MISSING이 있는데 모르고 진행하면 한참 뒤에 에러가 난다. 더 나쁜 경우는 다른 파일이 잡혔는데 눈치 못 채는 것이다.

이렇게

# 첫 셀에서 항상 config.describe()

10초면 된다. 습관으로 만들 것.

4. 결과 파일에 날짜를 붙인다

"up_down_beta_20260721.csv"

재실행할 때마다 파일이 쌓여서 어느 게 최신인지 모르게 된다.

이렇게

"up_down_beta_by_industry.csv"

같은 이름으로 덮어쓴다. 최신 결과가 항상 그 파일 하나뿐이라 헷갈릴 일이 없다. (docs/STYLE_GUIDE.md §9)

SECTION 06

config를 안 쓴다면

실제로 이렇게 해왔다. 잘 돌아가지만 팀으로 일할 때 문제가 생긴다.

지금까지 쓰던 방식

노트북 첫 셀에서 폴더를 직접 뒤져 파일을 찾는 코드다.

from pathlib import Path CURRENT_DIR = Path.cwd() candidate_roots = [CURRENT_DIR, CURRENT_DIR.parent, CURRENT_DIR.parent.parent] for root in candidate_roots: panel_candidates = [ root / "industry_rate_panel_daily.csv", root / "data" / "processed" / "industry_rate_panel_daily.csv", ] zip_candidates = [ root / "국고채 금리 1,3,5,10.zip", root / "data" / "raw" / "국고채 금리 1,3,5,10.zip", ] ... if found_panel and (found_zip or found_csv): PROJECT_ROOT = root; break TABLE_DIR = PROJECT_ROOT / "results" / "Yield_Curve" / "tables" FIGURE_DIR = PROJECT_ROOT / "results" / "Yield_Curve" / "figures" for folder in [PROCESSED_DIR, TABLE_DIR, FIGURE_DIR]: folder.mkdir(parents=True, exist_ok=True)
혼자 쓸 때는 문제없다

자기 PC에서 자기 파일로 자기 노트북만 돌린다면 이 코드로 충분하다. 아래 문제들은 팀원과 파일을 주고받을 때 생긴다.

여섯 가지 문제

문제 1
저장 경로가 조용히 복제된다 — 가장 위험

이 코드는 results/Yield_Curve/에 저장한다. 그런데 저장소 표준은 results/H1_yield_curve/다.

mkdir(parents=True, exist_ok=True)가 붙어 있어서 없는 폴더를 그냥 새로 만든다. 에러가 안 나니까 아무도 모른다. 결과물이 두 폴더에 흩어지고, 나중에 어느 게 최신인지 알 수 없게 된다.

문제 2
파일명이 코드에 박혀 있다

"국고채 금리 1,3,5,10.zip"처럼 한글과 쉼표가 들어간 이름을 직접 적었다. 팀원이 파일명을 조금만 다르게 저장하면 못 찾는다.

저장소 명명 규칙도 ASCII 전용·쉼표 금지다. 실제 파일명은 treasury_yield_curve_1_3_5_10y.csv로 이미 바뀌었으므로 이 코드는 지금 돌리면 실패한다.

문제 3
Path.cwd()에 의존한다

같은 노트북이라도 VS Code에서 열 때, Jupyter Lab에서 열 때, 터미널에서 돌릴 때 cwd가 각각 다르다.

위로 3단계까지만 뒤지므로 폴더가 더 깊으면 못 찾고, 반대로 프로젝트 밖의 동명 파일이 잡힐 수도 있다.

문제 4
파일이 늘어날 때마다 코드를 고쳐야 한다

회사채 AA− 원본을 추가하려면 candidates 목록에 직접 넣어야 한다. 노트북이 여러 개면 전부 똑같이 고쳐야 한다.

문제 5
무엇을 읽었는지 검증하지 않는다

print는 하지만 맞는 파일인지 확인하지 않는다. 엉뚱한 파일이 잡혀도 그대로 진행된다.

문제 6
노트북마다 이 블록이 복사된다

노트북이 7개면 같은 코드가 7벌 있다. 경로 규칙이 바뀌면 7군데를 다 고쳐야 하고, 하나라도 빠뜨리면 결과가 갈린다.

실제로 일어난 일

회의록에는 산출물 경로가 results/Yield_Curve/tables/...로 적혀 있다. 지금 저장소에 그 폴더는 없다. 재구성하면서 results/H1_yield_curve/로 통일했기 때문이다.

위 코드를 그대로 돌리면 없어진 폴더가 다시 생긴다. config를 쓰면 config.H1_TABDIR 하나만 바꾸면 되지만, 직접 쓰면 모든 노트북을 찾아다녀야 한다.

세 가지 선택지

방법설치경로 관리팀 공유추천
config + pip install -e .1회 한 곳에서 관리문제 없음권장
config + 부트스트랩 셀없음한 곳에서 관리 문제 없음대안
직접 탐색 (위 코드)없음노트북마다 따로 경로가 갈림비권장

이 표는 세 방식을 비교한다. 혼자 쓰면 셋 다 되지만, 팀으로 파일을 주고받으면 세 번째가 무너진다.

설치가 부담스럽다면 — 부트스트랩 셀

pip install 없이도 import config가 되게 만드는 방법이다. notebooks/06_yield_curve_exposure.ipynb 첫 코드 셀에 이미 들어 있으니 복사해서 쓰면 된다.

import sys from pathlib import Path _anchors = [] if "__vsc_ipynb_file__" in globals(): # VS Code _anchors.append(Path(globals()["__vsc_ipynb_file__"]).resolve().parent) if globals().get("_dh"): # Jupyter _anchors.append(Path(globals()["_dh"][0]).resolve()) _anchors.append(Path.cwd().resolve()) # 최후 수단 # config.py 와 requirements.txt 를 '둘 다' 가진 폴더만 루트로 인정 _root = next((p for a in _anchors for p in [a, *a.parents] if (p / "config.py").is_file() and (p / "requirements.txt").is_file()), None) if _root is not None: if str(_root) in sys.path: sys.path.remove(str(_root)) sys.path.insert(0, str(_root)) import config
기존 코드와 무엇이 다른가

마커를 두 개 본다. config.py 하나만 보면 다른 폴더의 동명 파일을 집을 수 있어서, requirements.txt까지 함께 있는 폴더만 루트로 인정한다.

VS Code·Jupyter의 실제 노트북 위치를 먼저 본다. cwd는 최후 수단으로만 쓴다.

경로를 만들지 않는다. 찾기만 하고, 실제 경로 정의는 config.py 한 곳에 맡긴다.

그래도 직접 쓰겠다면 — 최소 안전장치

세 가지만 지켜주세요

① 폴더를 자동 생성하지 말 것. mkdir 대신 없으면 에러를 내야 한다. 오타로 새 폴더가 생기는 사고를 막는다.

if not TABLE_DIR.exists(): raise FileNotFoundError(f"경로 확인 필요: {TABLE_DIR}")

② 저장 경로는 results/H1_yield_curve/ 형식으로. 회의록의 results/Yield_Curve/는 재구성 이전 표기다.

③ 무엇을 읽었는지 반드시 출력하고 눈으로 확인할 것. 파일 크기나 행 수도 같이 찍어두면 좋다.

SECTION 07

공유는 어떻게

우리 팀은 GitHub를 쓰지 않고 카톡으로 파일을 주고받는다. 그 상황에 맞춘 방법이다.

Q. 카톡으로만 공유하는데 config를 쓸 필요가 있나요?

오히려 더 필요합니다.

GitHub로 받으면 다들 비슷한 위치에 저장되지만, 카톡으로 압축파일을 받으면 푸는 위치가 제각각입니다. 다운로드 폴더, 바탕화면, 문서 폴더... 경로가 코드에 박혀 있으면 받는 사람이 매번 코드를 고쳐야 합니다.

config를 쓰면 압축을 어디에 풀든 그냥 실행됩니다.

문제config가 해결하나추가로 필요한 것
각자 폴더 위치가 다름해결없음
원본 파일명이 조금씩 다름해결없음
엉뚱한 파일을 읽는 사고해결없음
누가 최신 버전인지못 함 폴더 통째로 압축해서 공유

이 표는 config로 해결되는 것과 안 되는 것이다. 버전 관리는 config가 못 하므로 공유 방식으로 보완해야 한다.

Q. config.py도 카톡으로 보내야 하나요?

네. 다만 파일 하나만 보내지 마세요.

config.py는 notebooks/·src/·results/와 같은 폴더 구조 안에 있어야 작동합니다. 자기 위치를 기준으로 프로젝트 루트를 찾기 때문입니다.

config.py만 따로 보내면 받은 사람이 어디에 넣을지 몰라서 결국 안 됩니다.

Q. 그럼 어떻게 보내면 되나요?

이렇게 하면 안 됨

파일 하나씩 카톡으로 전송

06_yield_curve.ipynb config.py credit_spread_betas.csv → 어디에 넣어야 하죠?

받는 사람이 폴더 구조를 직접 맞춰야 한다. 한 개만 빠져도 안 돌아간다.

이렇게

폴더 통째로 압축해서 1개 파일로

FINDSLAB-Research-Intern.zip ├ config.py ├ notebooks/ ├ src/ ├ results/ └ data/ → 압축 풀고 바로 실행

구조가 그대로 유지된다. 어디에 풀든 동작한다.

Q. 매번 전체 폴더를 보내야 하나요? 용량이 큰데요.

아니요. 상황에 따라 다릅니다.

상황보낼 것빈도
새 팀원 합류 / 처음 세팅전체 폴더 압축1회
노트북만 수정해당 .ipynb 1개자주
결과만 공유results/ 안의 파일 또는 HTML 리포트자주
config.py 수정config.py 1개 + "config 바뀜" 공지드묾
원본 데이터 추가data/raw/ 해당 파일드묾

이 표는 상황별로 무엇을 보낼지 정리한다. 전체 압축은 처음 한 번이면 충분하고, 그 뒤엔 바뀐 파일만 보내면 된다.

config.py는 경로만 담고 있어서 거의 바뀌지 않습니다. 새 원본 파일이나 새 가설 폴더가 생길 때만 수정됩니다.

Q. config.py가 바뀌면 pip install을 다시 해야 하나요?

아니요. -e(편집 가능) 모드로 설치했기 때문에 폴더 안의 파일을 직접 바라봅니다. 새 config.py로 덮어쓰기만 하면 바로 반영됩니다.

재설치가 필요한 경우는 pyproject.toml이나 requirements.txt가 바뀌었을 때뿐입니다.

Q. 새 팀원이 합류하면 뭘 시키면 되나요?
1
전체 폴더 압축본 받기

카톡이나 드라이브로 FINDSLAB-Research-Intern.zip을 받는다.

2
압축 풀기 — 구조를 바꾸지 말 것

어디에 풀어도 되지만 안쪽 폴더 구조는 그대로 둬야 한다. config.py가 notebooks/·src/와 같은 높이에 있어야 한다.

3
패키지 설치
# 압축 푼 폴더 안에서 pip install -e . pip install -r requirements.txt
4
확인
import config config.describe()

MISSING이 없으면 준비 완료. 있으면 그 파일을 보내달라고 요청한다.

Q. 원본 파일명이 저와 다른데요?

대부분 config가 알아서 찾습니다. 별칭 탐색이 들어 있어서 .csv·.xlsx·.xls, 영문/국문 폴더명 차이를 흡수합니다.

describe()에서 OK(탐색)으로 나오면 별칭으로 찾은 것이니 그대로 써도 됩니다. MISSING이 나오면 파일이 실제로 없는 것이니 팀원에게 요청하세요.

카톡 공유에서 가장 조심할 것 — 버전이 갈리는 것

지우가 수정한 노트북과 연진이 갖고 있는 노트북이 다른데 아무도 모르는 상황이 제일 위험합니다. "같은 코드인데 결과가 다른데?"의 원인 대부분이 이것입니다.

보낼 때 무엇을 바꿨는지 한 줄 같이 적어주세요. 예 — "06 노트북에 PART D 추가함. config는 안 바뀜"

한 줄 요약

폴더 통째로 압축 · pip install -e . 한 번

처음에 전체 폴더를 압축해서 공유하고, 각자 PC에서 pip install -e .를 한 번 실행한다. 그 뒤로는 바뀐 파일만 보내면 된다.

규칙은 하나 — 경로를 손으로 쓰지 않는다. 이것만 지키면 압축을 어디에 풀든 팀원 누구의 코드든 그대로 돌아간다.
